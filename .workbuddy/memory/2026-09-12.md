## 收敛 CSS（试过，**已放弃，未落地**）

`style.css` 4615 行、1015 个「媒体条件 + 选择器」组合、`@media` 44 个
（`max-width:640px` 重复 17 次）、`:root` 3 次、`[data-theme="dark"]` 4 次、23 个 `!important`。

试的做法与结论：
1. 确认死代码：19 个类在模板/JS/Python 里**没有任何字面量**（也不属于 `变量拼后缀` 那类），
   例如 `.ai-answer` / `.source-item*` / `.container--narrow` / `.is-ok` / `.is-warn` /
   `.backup-card__note` / `.note-lead` / `.post-lead` / `.select--sm`。`is-*` 类动态添加时
   用的都是字面量（`classList.toggle('is-active')`），所以这个判定可信。
2. 写了「无损 CSS 扫描器 + 可证安全的收敛器」：删死规则、合并完全重复、合并 `:root`/暗色变量块，
   以及（带层叠安全判定的）合并同名选择器。
3. **静态等价检查通过**：合并前后「每个选择器最终生效的声明」**0 处变化**（14 个死选择器消失、
   0 个新增）。`style.safe.css`（14 死规则 + 2 重复 + 3 组变量块）与
   `style.force.css`（再合并 94 组同名选择器、去掉 103 条重复规则）都满足这一点。
4. **卡在哪**：真正的重复是「同一个选择器被补丁反复覆盖」，合并它必然改变与**中间其他规则**的
   层叠先后；能证明的只有「选择器自身声明不变」，先后关系只能靠浏览器逐元素比对。
   写了计算样式快照工具（`css_snapshot.py`，15 页面 × 8 视口 × 亮暗主题），但
   ①每个场景 `new_page()` 会把 Chromium 拖到 10 分钟以上（改成复用单页后 0.3~1.5s/场景）；
   ②即使提速，全矩阵两轮也要 3 分钟以上，而**验证的完备性仍不覆盖 :hover/:focus/无数据等状态**。
   用户决定不做，遂停手。

**重要：`app/static/css/style.css` 一字未改**，git 工作区干净。产物归档在 `.scratch/css-work/`
（`css_snapshot.py` / `css_refactor.py` / `dead-classes.txt` / `style.safe.css` / `style.force.css`），
想捡起来随时可用。
