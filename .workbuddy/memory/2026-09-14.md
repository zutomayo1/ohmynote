## 原生气泡窗口期清零（65d6278，用户报「按钮内移动仍弹旧版默认面板」）
- **title 摘取时机**：不能等 show()（延迟后）才摘——延迟窗口里原生气泡会抢跑
  （浏览器刚弹过一次后再触发极快）。一进元素立刻 stashTitle，cancelShow/hide 还原。
- **联动三处必须同步改**（摘 title 的涟漪）：
  1) readInfo 要兜底读 data-tip-stash-title，否则 show 时读不到 title 直接 return null，
     面板永远不出现（表象：自绘面板消失）；
  2) closestTipped 选择器必须含 [data-tip-stash-title]，否则 stashed 元素在 pointerout
     时跳过自身解析到外层 tipped 祖先，取消/还原全落空（表象：离开后面板仍弹出）；
  3) cancelShow 要还原 pending 元素的 title（延迟期间离开这条路径）。
- 排查手法：给 stash/restore/show/hide/cancelShow 临时插桩 window.__ctl + 探针记录
  pointerover/out 的 closest 结果，一轮就定位；比逐个猜快得多。
- **教训：同一条消息里对同一文件发多个 Edit 会丢更新**（cancelShow 的修改被吃掉，
  工具报成功但内容不在）。同一文件多处修改要么串行、要么一次 Edit 完成、改完 Read 复核。
