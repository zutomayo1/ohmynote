  断言处中断，导致同一脚本后半段的 base.html 接线没执行，事后排查了半天
  （表象是「脚本没加载」，实际是接线根本没写）。
- 补丁校验要**剥掉注释再查 forwards/both**：agent 会在注释里写「禁止 forwards」，
  朴素字符串检查会误报。

  缺样式与测试；onboarding/templates-sort 代码完整但 e2e 脚本自身有 bug
  （缺 import、用了不存在的 Locator.drag_and_drop）——接手时要逐个甄别。

## 幽灵 CSS 令牌清理 + 守卫（提交 1ac6197 / 50a2988）
- 并行 agent 的补丁里用了**别处的通用令牌**：--text/--border/--muted/--hover/
  --border-strong（有硬编码浅色兜底 → 暗色主题变浅色块）、--ok（无兜底 →
  var() 整条声明失效，保存成功不变绿）。共修 16 处，映射到项目真实令牌。
- 保留合法的无定义覆盖项：--dot/--split/--cols/--arrow-x/--i（模板内联或
  JS setProperty 注入）、--danger-50（兜底是 var(--surface-2)，不是硬编码）。
- **我自己踩的坑**：写替换脚本时把真实存在的 --accent 也映射成了 --brand（40 处），
  用 `git checkout -- <file>` 整文件回滚后重做。教训：批量替换前先确认「幽灵集合」
  是脚本算出来的，不要用想当然的映射表。
- 新增两条守卫（tests/test_css_rules.py）：未定义且无兜底的 var() → 失败；
  未定义令牌的 hex 兜底是浅色 → 失败（令牌有定义时兜底永不生效，不误报）。
